# B-10 幅宽面积核算

对接 C-05 轨迹核算。复用原有 `AreaCalculationServiceImpl` 幅宽覆盖算法，补充分段核算与扣减明细，以及两个只读接口。无需新建表，不修改现有作业单、归档点、面积或结算记录。

## 1. 核算口径

幅宽单位为**厘米**，3米填写 `300`。输入坐标为 WGS84 经纬度，面积在与原算法相同的局部米制投影中计算。

1. 各片段内部相邻定位点构成作业段，各段生成宽度为幅宽的矩形覆盖带。
2. 片段间不连线；全部覆盖带统一取并集，重复走过的区域只计一次。
3. 覆盖并集与地块边界求交，原生空洞自动扣除。
4. 若地块类型为“插花地”，再扣除未删除的额外排除区并集，重叠排除区不重复扣减。
5. 平方米乘 `0.0015` 换算为亩，与原有归档逻辑一致。

这里的“长度×幅宽”是**输入片段的毛覆盖面积**。最终有效面积须经过覆盖去重和边界裁剪。例如100米、3米幅宽的直线为300平方米；原路返回，累计长度变为200米，毛面积600平方米，但有效覆盖仍为300平方米。

不能把 B-09 的界内中心线长度直接乘幅宽当最终面积：中心线沿田边时可能只有一半幅宽在田里；中心线在界外但幅宽伸入田里时，仍有实际覆盖部分。B-10 裁剪的是覆盖带。

扣减按“重复覆盖 → 界外及原生空洞 → 额外排除区”顺序归因，因此各项互斥。面积各阶段先保留两位小数，再计算展示扣减，保证：

```text
毛面积 = 重复覆盖扣减 + 界外扣减 + 排除区扣减 + 有效面积
```

不自动识别转场、停留、超速或漏采，也不推断缺失幅宽。这些属于 B-11、B-12。试算输入应为已经确认的同地块、同幅宽作业片段；结果不是最终结算指令。

## 2. 提交片段试算

```text
POST /trajectory/accounting/preview
Content-Type: application/json
Authorization: Bearer <登录Token>
```

`plotId` 必须替换为本人有权访问的实际地块ID，建议使用字符串提交雪花ID。

```json
{
  "plotId": "1234567890123456789",
  "widthCm": 300,
  "segments": [
    [
      {"longitude": 114.0001, "latitude": 38.0005},
      {"longitude": 114.0009, "latitude": 38.0005}
    ]
  ]
}
```

若此ID对应之前导入的示例矩形（经度114～114.001、纬度38～38.001），这条线在矩形内部，三项扣减应为零，毛面积与有效面积相等。多段轨迹放在 `segments` 的不同数组中，禁止将漏采前后的片段拼成一条连续线。

输入限制：

- `widthCm` 为1～10000的 JSON 整数；`300.9`、`"300"`、零、负数或缺省值均拒绝，不静默截断。
- 最多1000个片段、总计10000点。超限明确报错，不静默截断。
- 经度和纬度必须同时提供且为有限 WGS84 坐标；缺失坐标不会被转换为0。
- 片段数组、点不可为null。允许空数组、单点、重复位置，合法几何下返回零覆盖；仍会检查地块边界有效性。
- 不排序坐标，不依据时间推断行驶顺序或分段。C-05 可从 B-08 的 `tracks[].segments` 提取经纬度。

## 3. 按归档作业单重算

```text
GET /trajectory/accounting?trajectoryId=<实际归档作业单号>
Authorization: Bearer <登录Token>
```

幅宽、地块由作业单读取；有效轨迹通过 B-08 读取同一ID的 PostGIS 归档，不使用暂存点、其他作业单或默认幅宽替代。归档查询沿用 B-08 的24小时时段限制。

保留 B-08 的分段：超过5分钟间隔或同刻异位点的片段不连接，片段之间的重叠覆盖仍统一去重。这是回放断段规则，不能替代 B-11 的异常判定。

无归档、归档无可用点、格式损坏、跳过了无效点、地块不匹配、幅宽缺失或无效时返回错误，不能伪装成正常的零面积。如果记录面积存在，返回 `recordedAreaMu` 和 `differenceFromRecordedAreaMu`（本次亩数减历史亩数），仅供复核。

重算使用**当前边界与当前启用的排除区**，不是对历史边界的还原。历史版本属于 B-06；当前差值不能直接用来批量覆盖历史面积。

## 4. 返回字段

沿用 `{code,msg,data}`。`data` 包含：

| 字段 | 含义 |
| --- | --- |
| trajectoryId | 归档作业单ID；提交片段试算时为null |
| plotId | 字符串地块ID |
| source | `SUBMITTED_SEGMENTS` 或 `POSTGIS_ARCHIVE` |
| coordinateSystem | `WGS84` |
| preview | 始终为true，表示只读试算 |
| widthCm | 厘米幅宽 |
| segmentCount / pointCount | 输入片段数／总点数，包括单点和空片段 |
| calculation | 下表核算明细 |
| recordedAreaMu | 历史记录亩数；没有历史值则为null |
| differenceFromRecordedAreaMu | 与历史记录的差值，亩；没有历史值则为null |
| warnings | 数据来源、分段、试算及校准提示，应展示给用户 |

`calculation`：

| 字段 | 单位与含义 |
| --- | --- |
| travelLengthMetres | 米，输入各片段中心线累计长度，保留3位小数，未按边界裁剪 |
| grossAreaSquareMetres | 平方米，未舍入累计长度×厘米幅宽÷100 |
| uniqueAreaSquareMetres | 平方米，去重后的覆盖并集面积 |
| inBoundaryAreaSquareMetres | 平方米，与原生地块边界求交后的面积 |
| overlapDeductionSquareMetres | 平方米，重复覆盖扣减 |
| outsideDeductionSquareMetres | 平方米，界外及原生空洞扣减 |
| exclusionDeductionSquareMetres | 平方米，插花地额外排除区扣减 |
| effectiveAreaSquareMetres | 平方米，最终有效覆盖，保留2位小数 |
| effectiveAreaMu | 亩，保留4位小数 |

长度和面积独立舍入，使用已显示的3位长度回乘，可能与毛面积出现末位差异。

## 5. 权限与副作用

两个接口要求登录。地块权限复用 B-09：管理员可查询有效地块，普通用户只能访问本人创建，或本人创建／绑定终端作业单关联的未删除地块。归档核算另检查作业单属于本人创建或本人绑定终端；管理员可查询其他有效作业单。不存在、无权访问和已删除作业单返回相同403提示。

调用只读，不保存试算输入、不改变地块、轨迹、作业状态或结算。原来的单段面积计算签名与归档流程保留，本次没有替换历史结算流程，也没有执行共享数据库建表或数据修复。

## 6. 网页测试步骤

1. 使用仓库的 `.tools/start-cms.cmd` 重新构建启动后端，等到 `Started AgriCMSApplication`。
2. 打开 `http://localhost:8088/swagger-ui.html`，选择“06-轨迹管理”。
3. 在平台网页正常登录，按 F12 打开开发者工具，进入 Network（网络），刷新地块列表；点开任意已登录的接口请求，在 Request Headers（请求标头）中复制 `Authorization` 的完整值。回到 Swagger 点击 Authorize，粘贴这个 `Bearer ...` 值。
4. 先从地块列表找到本人导入的示例田，复制实际地块ID。
5. 展开 `POST /trajectory/accounting/preview`，点击 Try it out，用上面的JSON替换ID后执行。应返回200，幅宽300，扣减为零。
6. 在同一片段末尾追加起点，构成往返。毛面积约翻倍，有效面积保持不变。
7. 把 `widthCm` 改为0或300.9，应返回错误。仅保留纬度、删除经度，也应返回错误。
8. 有本人真实归档作业单时，再执行 `GET /trajectory/accounting`，核对记录幅宽、数据来源和历史面积差值。没有归档会明确报错，不会自动造示例轨迹。

本次提供后端接口与 C-05 对接契约，未在轨迹页面新增核算按钮。网页可通过 Swagger 调试；实际前端入口由 C-05 对接。
